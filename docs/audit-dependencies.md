# Dependency, runtime, configuration, and asset audit

Audit run on Windows x64, 2026-09-05. Baseline: the published `coil-compiler==0.2.4` wheel extracted to `build/audit/published`. Host: CPython 3.12.10. Executed bundles use the official CPython 3.12.10 and 3.13.7 embeddable runtimes. Python 3.9.13 was also used to execute Coil's CLI imports and build preview. These are observed results from built executables, except where a build or the CLI itself fails before an executable can exist.

## Reproduce

From the repository root, with the published wheel extracted as above and a Python environment containing Coil's dependencies:

```powershell
build/audit/venv/Scripts/python.exe tools/audit_dependencies.py baseline
build/audit/venv/Scripts/python.exe tools/audit_dependencies.py current
$env:PYTHONPATH = 'src'
$env:COIL_TEST_CROSS_RUNTIME = "$PWD/build/audit/dependencies/runtime-cache/python-3.13.7-embed-amd64.zip"
build/audit/venv/Scripts/python.exe -m pytest tests/test_dependency_regressions.py tests/test_dependency_build_integration.py tests/test_resolver.py tests/test_scanner.py tests/test_builder.py tests/test_runtime.py tests/test_cli.py tests/test_inspect.py -q --basetemp build/audit/dependencies/pytest-verification
```

The harness downloads fixed runtime versions if absent, creates small local wheels with controlled versions and ABI tags, runs pip against only those wheels, invokes the real `builder.build` pipeline, and executes each produced `.exe`. Its only runtime-selection substitution maps `3.12` to `3.12.10` and `3.13` to `3.13.7`, avoiding an unrelated network search for patch versions. Cache and temporary output belong under `build/audit/dependencies`; the pre-existing user runtime cache is read only. The final CLI preview build can read that existing 3.12.10 runtime ZIP.

Source fixtures, complete build logs, bundles, and JSON observations are retained under `build/audit/dependencies/{baseline,current}`. `results.json` contains each exit code, stdout, stderr, app-written result, and remaining `.py` paths. The `case` column below is the key in that file and the corresponding project/bundle name. The regression command above passed **141 tests**, including two real executable integration tests.

## Findings, ranked by impact on an application author

| Severity | Case | Published 0.2.4 observation | Change or disposition |
| --- | --- | --- | --- |
| High | `assets_secure` | A secure build copies `pkg/__init__.py` and explicitly ignored `pkg/private/helper.py` plus `secret.txt` into the bundle because the directory also contains `data.json`. The application actually imports the copied **source** from bundle root, overriding the compiled package. | Fixed in packaging: recurse per file, apply exclusions to descendants, copy assets beside compiled code as well as the existing root asset layout. The executable now imports `_internal/app/pkg/__init__.pyc`, finds its resource, and contains none of those source/ignored files. |
| High | `pin` | Requirements specify `coilauditdep==1.0`; available wheels are 1.0 and 2.0. The real application reports **2.0**, because Coil discards the constraint before pip. | Fixed. Both requirements and project dependencies preserve pins, extras, markers, and named URLs. Auto-detection cannot add an unconditional duplicate that defeats a declared conditional requirement. Current exe reports **1.0**. |
| High | `cross_version` | Build using host 3.12 for target 3.13 succeeds; execution fails with `bad magic number in 'coilauditdep': b'\xcb\r\r\n'`. Project bytecode uses the target interpreter, dependency bytecode uses the host. | Fixed in packaging: dependency compilation uses the target runtime. Current executable returns **1.0**, exit 0. |
| High | `cache312`, `cache313` | A clean 3.12 build caches a `cp312` wheel. A subsequent clean 3.13 build prints a cache hit and reuses it. That executable fails. The cached source explicitly reports `cp312`, independently establishing that the wrong wheel was reused. | Fixed: dependency cache identity includes target version, OS, and architecture; case-sensitive requirement suffixes are retained. | High | `dependency_subdirectories` | A valid wheel's package imports its `docs` and `tests` Python subpackages at runtime. Coil removes them by directory name. Baseline error misleadingly suggests an omitted third-party extension. | Directly detected project/dependency imports are now retained, including the `pydoc` runtime helper. Current real `stdlib_direct` exits 0; `pydoc` also works in the dynamic probe. **Full retention remains a policy decision:** dynamically selected `venv`/`lib2to3` still fail when not detected. |

| Medium | Python 3.9 CLI | Running `import coil.cli` under real CPython 3.9.13 fails before argument parsing with `TypeError: unsupported operand type(s) for \|`. Actual 3.9 CLI/build module imports and `--dry-run --python 3.9.13` now succeed with those dependencies. A full pip installation/build driven by 3.9 was not part of this audit. |

## Confirmed behavior and choices retained

`function_literal` imports a dependency through `importlib.import_module('coilauditdep')` **inside a function**. Both baseline and current real executables run successfully. Ordinary imports nested in functions are also visited by AST scanning; the scanner does not stop at top-level statements. Known import/distribution mappings and metadata-based naming are covered by resolver tests; the full executable suite exercises real pywin32 imports and `.pth`/DLL setup separately.

`optimized` confirms the default build sets `__debug__` false and skips `assert False`, while retaining function docstrings. Secure compilation additionally strips docstrings. This is an existing optimization policy, documented by `--optimize`; it was retained. An application requiring assertion behavior must use `--optimize 0`.

Secure mode is bytecode distribution, not encryption. It avoids the default recovery source archive, but code constants and bytecode remain readable and absolute build paths can appear in tracebacks. The raw-source leak above was a separate concrete defect and is fixed. Renaming this mode, changing optimization defaults, or adding an encryption mechanism would be product decisions.

Requirements files remain an exclusive dependency source when present; automatic scanning is additive to `[project].dependencies` otherwise. The fix preserves requirement semantics and nested `-r` files. Unsupported pip directives such as `-e` or `-c` now produce an explicit error instead of silently omitting their effect. Arbitrary pip configuration/lockfile support and new source-root semantics are not implemented here.

Root-level non-code assets such as `.ico`, `.json`, and images are copied unless excluded; an external icon selected only for PE stamping is not automatically a project asset. Existing default exclusions include project tests, build outputs, virtual environments, configuration/build files, many documentation names, and `.env`. `.coilignore` can re-include defaults, provided excluded ancestors are also re-included. Subdirectory copying now follows those same rules; assets beside package modules are also present beside the compiled modules for `__file__` and resource access.

## Coverage limits and remaining review points

| Area | Evidence and limit |
| --- | --- |
| Runtime downloads | Real interrupted-cache build fails then repairs after the fix. ZIP CRC checks and atomic publication prevent accepting partial writes; downloads still rely on HTTPS and do not verify a separately trusted publisher digest/signature. No network-adversary experiment was performed. |
| Runtime patch discovery | The built apps used fixed versions. The pre-existing short-version resolver probes patches from 20 down to 0 with repeated HTTP HEAD requests. Future patches above 20 and network latency are source-review concerns, not experimentally reproduced failures here. |
| Clean cache | Actual ABI separation reproduced before/after. Atomic publication is implemented; the broader build-cache concurrency stress was not exercised by this dependency harness. Unpinned packages can remain cached until the cache is cleared; this existing policy remains. |
| Source scanning | Real function/literal, variable import, excluded imports, stdlib classification, namespace, and source-root cases are covered. Encoding-cookie handling has a regression test. Arbitrary dynamic expressions, plugins discovered from external metadata, aliased import callables, and host/target grammar differences are not exhaustively inferred. |
| Requirements | Real version-selection result checked against two controlled wheels. Extras, markers, nested includes, canonical exclusions, and URL fragments have targeted tests. Cross-target pip environment-marker behavior and arbitrary VCS/local/editable requirements were not certified. |
| Dependencies | Real pure-Python wheels and ABI-tag selection plus cross-version bytecode covered. The root test suite covers real pywin32. Exhaustive third-party/native-extension compatibility is not claimed. |
| Configuration | Real dry-run and configured entry/profile inspect/build/execute covered. macOS and Linux remain intentionally unsupported; neither was claimed as tested. Unknown TOML keys/type mistakes, all possible relative path conventions, and version discovery above supported native launchers are not comprehensively validated. |
| Compiler/obfuscator | Real project and dependency compilation, secure source-leak fix, resource layout, and optimization observed. Secure bytecode has no cryptographic confidentiality guarantee. Default mode intentionally embeds recoverable sources. |

These observations do not certify every dependency, Python patch release, architecture, EDR product, or filesystem layout. Portable extraction, launcher arguments/process behavior, signing, and version drift are reported in the main audit and the portable audit.
